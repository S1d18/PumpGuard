# PumpGuard

Следит за помпой, вентиляторами и температурами (CPU, GPU, GPU Hot Spot, память GPU). Управляет скоростью вентиляторов по пресетам. Если помпа встала или что-то перегрелось, выключает ПК. Показывает всё в виджете на рабочем столе и отдаёт данные по HTTP API для других программ.

```
┌────────────────────────── служба PumpGuard (LocalSystem, автозапуск) ──────────────────────────┐
│  LibreHardwareMonitor ─┐                                                                        │
│  (CPU, матплата, помпа,├─► SafetyMonitor ──► выключение ПК (shutdown /s /f)                     │
│   вентиляторы, Hot Spot)│        │                                                              │
│  NVML (GPU, память) ────┘        └──► FanController ──► скорость вентиляторов / помпы           │
│                                   HTTP API 127.0.0.1:8765 ◄───────────────────────────────────  │
└───────────────────────────────────────────────▲────────────────────────────────────────────────┘
                                                │
                        виджет (WPF) · ваши скрипты · любые программы
```

Решение о выключении принимает **служба**. Защита работает, даже если виджет закрыт и никто не вошёл в систему.

## Установка

Нужны .NET 9 SDK и драйвер [PawnIO](https://pawnio.eu), через который LibreHardwareMonitor читает датчики. На этом ПК PawnIO уже стоит.

Откройте PowerShell **от имени администратора**:

```powershell
git clone https://github.com/S1d18/PumpGuard.git
cd PumpGuard
.\install.ps1
```

Скрипт:
- ставит программу в `C:\Program Files\PumpGuard`;
- создаёт службу `PumpGuard`, которая стартует с Windows ещё до входа в систему и автоматически перезапускается при сбое;
- добавляет виджет в автозагрузку пользователя (отключается ключом `-NoWidgetAutostart` или галочкой в меню виджета);
- создаёт `C:\ProgramData\PumpGuard\config.json`. Повторная установка его не перезаписывает.

Удаление: `.\uninstall.ps1`, с ключом `-Purge` удалятся ещё конфиг и пресеты.

## Первая настройка: датчик помпы

Без этого шага защита помпы не работает, виджет покажет «датчик не настроен».

```powershell
& 'C:\Program Files\PumpGuard\service\PumpGuard.Service.exe' --list-sensors
```

Запускать от администратора. Найдите в списке раздел матплаты (ITE IT8665E на ROG STRIX X399-E) и строки `Fan`:

```
== ITE IT8665E
  Fan         /lpc/it8665e/0/fan/0       Fan #1     1150 RPM
  Fan         /lpc/it8665e/0/fan/5       Fan #6     2400 RPM   ← помпа (AIO_PUMP / W_PUMP+)
  Control     /lpc/it8665e/0/control/5   Fan #6     100 %
```

Чтобы понять, какой номер соответствует помпе, сравните с BIOS (Monitor → Fan Speed) или ненадолго отключите тахо-провод помпы. Впишите Id в `config.json`:

```json
"Pump": { "SensorId": "/lpc/it8665e/0/fan/5", "MinRpm": 500, "FailAfterSeconds": 5 }
```

`MinRpm` ставьте примерно в половину от обычных оборотов помпы. После изменения конфига выполните `Restart-Service PumpGuard`.

Если непонятно, какой разъём чей, запустите `--identify-fans` (от администратора). Разъёмы по очереди снижаются до 30 % на 12 с, консоль показывает, какой именно сейчас снижен. У помпы есть «пол» оборотов (D5/DDC около 2000), вентилятор же падает в разы. `--test-fan <ControlId> <процент> …` держит один разъём на заданных значениях и печатает обороты два раза в секунду.

> **Проверьте помпу на 100 %.** На этом ПК тахометр помпы (Fan #6) на 100 % ШИМ выдаёт мусор: 600…6000 об/мин, иногда долго держится 0. Это вызвало ложное аварийное выключение. На 99 % показания стабильные. Поэтому у канала помпы стоит `"MaxPercent": 95`, а помпа никогда не отдаётся BIOS: при пресете `Bios` служба держит её на `MaxPercent`. Для своей помпы проверьте: `--test-fan /lpc/…/control/N 95 100`.

## Как принимается решение

| Событие | Что происходит |
|---|---|
| Температура ≥ `WarnC` | предупреждение (жёлтый), вентиляторы на максимум |
| Температура ≥ `ShutdownC` дольше `ShutdownHoldSeconds` | **тревога**: звук, виджет всплывает поверх окон, отсчёт `ShutdownCountdownSeconds` (30 с), затем выключение |
| Помпа < `MinRpm` дольше `FailAfterSeconds` | **тревога** с отсчётом; помпа и вентиляторы на 100 % |
| Датчик помпы молчит дольше `SensorLostAfterSeconds` | тревога (или только предупреждение, если `TreatSensorLossAsFailure: false`) |
| Температура ≥ `CriticalC` дольше `CriticalHoldSeconds` | **немедленное выключение** без отсчёта, отменить нельзя |
| Кнопка «Отменить выключение» / `POST /api/alarm/cancel` | отсчёт останавливается, тревоги откладываются на `CancelSnoozeSeconds` (5 мин). Критическая температура по-прежнему выключает ПК |
| Проблема ушла во время отсчёта | отсчёт отменяется сам |

Защита от ложных срабатываний:
- температура ≤ 0 °C или > 150 °C считается ошибкой чтения, а не показанием;
- для выключения значение должно держаться несколько секунд подряд: одиночный выброс ничего не выключит.

### Пороги по умолчанию

| Правило | Датчик | Warn / Shutdown / Critical | Почему |
|---|---|---|---|
| CPU | Tdie (`/amdcpu/0/temperature/1`) | 65 / 75 / 85 °C | у 2990WX Tctl = Tdie + 27 °C, поэтому берём Tdie. Троттлинг около 68 °C Tdie |
| **GPU Hot Spot** | NVAPI (`/gpu-nvidia/0/temperature/2`) | 90 / 100 / 105 °C | самая горячая точка кристалла. В простое на ~12 °C выше Core |
| GPU | NVML + NVAPI Core, берётся максимум | 75 / 83 / 88 °C | V100: макс. рабочая 83, троттлинг 87, аппаратное отключение 90 |
| GPU Memory | NVML (HBM2) | 75 / 85 / 90 °C | HBM2 V100: макс. рабочая 85 °C |

У правила может быть несколько датчиков (`"SensorIds": [...]`). Тогда берётся **самое горячее** значение, а если один из датчиков пропал, виджет об этом предупредит. «Memory Junction» из NVAPI (`/gpu-nvidia/0/temperature/3`) на V100 показывает примерно на 14 °C больше, чем NVML и GPU-Z, поэтому в правило памяти он не включён.

## Вентиляторы и помпа: мониторинг и управление

Каналы описываются в `FanControl:Channels` файла `config.json`. Id берутся из `--list-sensors`:

```json
"FanControl": {
  "Enabled": true,
  "ActivePreset": "Balanced",
  "Channels": [
    { "Name": "CPU радиатор", "ControlId": "/lpc/it8665e/0/control/0", "FanSensorId": "/lpc/it8665e/0/fan/0",
      "SourceSensorIds": ["/amdcpu/0/temperature/1", "/gpu-nvidia/0/temperature/2"],
      "MinPercent": 30, "FailMinRpm": 300 },
    { "Name": "Помпа", "ControlId": "/lpc/it8665e/0/control/5", "FanSensorId": "/lpc/it8665e/0/fan/5",
      "SourceSensorIds": ["/amdcpu/0/temperature/1"], "MinPercent": 70, "IsPump": true,
      "Curves": { "Silent": [ { "TempC": 30, "Percent": 70 }, { "TempC": 60, "Percent": 100 } ] } },
    { "Name": "Корпус задний", "FanSensorId": "/lpc/it8665e/0/fan/2", "FailMinRpm": 200 }
  ]
}
```

- Канал **без `ControlId`** только отслеживается: обороты показываются, при остановке выдаётся предупреждение (`FailMinRpm`).
- `SourceSensorIds` — по каким температурам работает кривая (берётся максимум). Для радиатора, через который идут и CPU, и GPU, укажите оба.
- `MinPercent` — нижняя граница, ниже которой не опустят ни кривая, ни ручной режим. Для помпы ставьте высокой.
- `Curves` — своя кривая канала для конкретного пресета, если общая не подходит.
- `Enabled: false` — только мониторинг, вентиляторами управляет BIOS.

**Пресеты:** `Silent`, `Balanced`, `Performance` (кривые температура → %), `Full` (100 %), `Bios` (управление отдаётся матплате). Свои пресеты добавляются в `FanControl:Presets` или через API. Переключать можно в меню виджета (правая кнопка → «Пресет вентиляторов») или в окне «Управление вентиляторами…», где у каждого канала есть ручной ползунок.

Защитные правила вентиляторов:
- при перегреве (`ShutdownC`/`CriticalC`) или тревоге все каналы сразу уходят на `MaxPercent`, какой бы пресет ни был выбран. На уровне `WarnC` это происходит, только если перегрев держится `WarnHoldSeconds` (3 с): Tdie у Threadripper прыгает на 10 °C за секунду. Режим «максимум» держится не меньше `MaxHoldSeconds` (10 с);
- при отказе помпы канал с `IsPump` уходит на 100 %;
- если для кривой нет температуры, канал работает на максимуме;
- скорость повышается сразу, а понижается плавно (`RampDownPercentPerTick`);
- при остановке службы все каналы возвращаются под управление BIOS.

Выбранный пресет, ручные значения и свои пресеты сохраняются в `C:\ProgramData\PumpGuard\fan-state.json`.

## Виджет

Три режима вида (правая кнопка → «Вид», или двойной щелчок переключает полоску и полный вид):

- **Полоска**: одна строка `● Помпа 3261 │ CPU 47 °C · 54 W │ GPU 41 °C · 21 W`. Для каждого блока берутся первая температура и первая мощность. При тревоге полоска сама раскрывается, чтобы были видны отсчёт и кнопка отмены.
- **Обычный**: карточка с блоками CPU, GPU и вентиляторы. В каждой строке значение и график за 3 минуты. При наведении на график подсказка показывает мин/макс/сейчас.
- **Широкий**: те же блоки колонками рядом, графики крупнее.
- **Закреплённую панель можно двигать и менять ей размер.** Потяните за внутренний край (курсор ↔ / ↕), чтобы изменить ширину боковой панели (90–600 px) или высоту горизонтальной (26–48 px). Потяните за любое другое место, и панель перепрыгнет к ближайшему краю экрана. Боковая панель уже 180 px показывает узкие плитки: помпа, CPU, GPU Hot Spot с графиками и обороты вентиляторов. Пункт «Узкая боковая панель» быстро переключает 100 ↔ 300 px.
- **Панель сбоку** (слева или справа): колонка шириной 300 px во всю высоту экрана, до панели задач. В ней полный вид: помпа, блоки CPU и GPU с графиками, вентиляторы, тревога с кнопкой отмены. Место под неё резервируется так же, как у панели вдоль экрана.
- **Панель вдоль экрана** (сверху или снизу): полоса во всю ширину основного монитора. В ней помпа, все значения блоков CPU и GPU с графиком по первой температуре блока, обороты вентиляторов и состояние. По умолчанию панель резервирует место как панель задач, и развёрнутые окна её не перекрывают. Отключается пунктом «Окна не перекрывают панель». При тревоге панель краснеет, в ней появляются причина, отсчёт и кнопка «Отменить выключение». Двойной щелчок возвращает обычный вид.

Ошибки самого виджета пишутся в `%APPDATA%\PumpGuard\widget.log`.

Состав блоков задаётся в `config.json`: у правил температуры это `"Group"` и `"Label"` (подпись внутри блока), у `Extras` это `"Group"`. Порядок блоков берётся из конфига. Шкала графика подстраивается под данные, но не уже 10 °C / 20 W / 20 %, чтобы шум датчика не выглядел скачками. История (10 минут) хранится в службе, поэтому после перезапуска виджета графики сразу заполнены.

Перетаскивается мышью, позиция запоминается. Меню по правой кнопке: пресет вентиляторов, окно управления, «Поверх всех окон», «Запускать при входе в Windows», выход. При тревоге виджет сам всплывает поверх окон, пищит и показывает отсчёт с кнопкой отмены. Если служба не отвечает или данные старше 5 секунд, виджет показывает это серым или красным. `PumpGuard.Widget.exe --fans` сразу открывает окно вентиляторов.

Настройки виджета хранятся в `%APPDATA%\PumpGuard\widget.json` (`ApiUrl`, `Token`).

## HTTP API

Доступно только локально (`127.0.0.1:8765`). Запросы с чужим `Host` отклоняются. Для POST/PUT/DELETE обязателен заголовок `X-PumpGuard-Token`: если в конфиге задан `ApiToken`, значение должно совпадать, иначе подойдёт любое. Этот заголовок не даёт веб-страницам в браузере дёргать API.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/health` | `200 {ok:true}`, если данные свежие, иначе `503` — удобно для сторожей |
| GET | `/api/status` | полное состояние: `state` (`Normal`/`Warning`/`Alarm`/`ShuttingDown`), помпа, температуры, вентиляторы, проблемы, `secondsToShutdown` |
| GET | `/api/history?seconds=180` | история до 10 минут: `timestamps` и массивы значений по ключам `pump`, `temp:CPU`, `extra:GPU/Мощность`, `fan:Fan #1`… |
| GET | `/api/stream` | то же в виде Server-Sent Events, раз в секунду |
| GET | `/api/sensors?kind=Fan` | все сырые датчики (`Temperature`, `Fan`, `Control`, `Load`, `Power`…) |
| POST | `/api/alarm/cancel` | отменить отсчёт выключения |
| GET | `/api/fans` | пресеты, активный пресет, ручные значения, каналы |
| POST | `/api/fans/preset` | `{"name":"Silent"}` |
| POST | `/api/fans/manual` | `{"channel":"CPU радиатор","percent":60}`; `percent: null` возвращает канал к пресету |
| PUT | `/api/fans/presets/{name}` | `{"mode":"Curve","curve":[{"tempC":40,"percent":35},{"tempC":70,"percent":100}]}` |
| DELETE | `/api/fans/presets/{name}` | удалить свой пресет |
| POST | `/api/simulate/pump-failure?seconds=60` | только в DryRun: имитация остановки помпы |

Примеры:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/status
Invoke-RestMethod -Method Post -Headers @{ 'X-PumpGuard-Token' = 'x' } http://127.0.0.1:8765/api/alarm/cancel
```

```python
import json, requests
# Например: остановить обучение модели, пока ПК не выключился
for line in requests.get("http://127.0.0.1:8765/api/stream", stream=True).iter_lines():
    if line.startswith(b"data: "):
        s = json.loads(line[6:])
        if s["state"] == "Alarm":
            print("Тревога:", s["shutdownReason"], "— выключение через", round(s["secondsToShutdown"]), "с")
            # save_checkpoint(); ...
```

## Проверка без риска

Запустите службу в тестовом режиме: вместо выключения она только пишет в лог, и включается симуляция.

```powershell
Stop-Service PumpGuard
& 'C:\Program Files\PumpGuard\service\PumpGuard.Service.exe' --dry-run
# в другом окне:
Invoke-RestMethod -Method Post -Headers @{ 'X-PumpGuard-Token' = 'x' } 'http://127.0.0.1:8765/api/simulate/pump-failure?seconds=60'
```

Виджет покажет тревогу и отсчёт, в логе появится `[DRY RUN] Здесь ПК был бы выключен`. После проверки: `Start-Service PumpGuard`.

Журнал службы: «Просмотр событий» → «Журналы Windows» → «Приложение». Туда пишутся предупреждения, смена состояния и выключения.

## Важно

- Это программная защита. Если Windows зависнет целиком, она не сработает. Включите в BIOS аппаратную защиту: предупреждение об отказе CPU/помпы (Q-Fan → *Fan Speed Low Limit*) и штатный тепловой отключатель.
- Hot Spot читается через NVAPI. Если в службе (session 0) он не прочитается, виджет покажет «GPU Hot Spot: нет данных». GPU при этом всё равно защищён правилом по Core (NVML).
- Под обычным пользователем `--list-sensors` не видит матплату, а CPU показывает мусор (Tdie −27 °C). Запускайте его от администратора. Служба работает от LocalSystem, у неё прав хватает.

## Разработка

```powershell
dotnet test                                   # 33 теста логики безопасности и вентиляторов
dotnet run --project src/PumpGuard.Service -- --dry-run
dotnet run --project src/PumpGuard.Widget
```

- `src/PumpGuard.Core` — логика без ввода-вывода: `SafetyMonitor` (когда выключать), `FanController` (скорость вентиляторов).
- `src/PumpGuard.Service` — датчики (`Hardware/`), цикл мониторинга, API, выключение.
- `src/PumpGuard.Widget` — WPF-виджет.
